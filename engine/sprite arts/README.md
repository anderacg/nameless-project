# Character Sprite & Rig Studio

Open **[sprite-workshop.html](sprite-workshop.html)** for the complete offline creator. The skeleton editor is first; **Appearance & equipment** jumps to the existing character generator.

Load [examples/animated-hero.rig.json](examples/animated-hero.rig.json) with **Load rig project** for an editable wave animation and a bone-attached wrist cuff.

## Skeleton and animation authoring

The rig is built from the current `PX.DOLL.SKEL`, racial row/width rules and the indexed pixels generated by `PX.dollBase`. It keeps the original art and source resolution. Eyes are off by default; explicitly saved appearance recipes keep their own setting. At zero pose, every current race's body pixels match the original generator exactly.

Fifteen hierarchical bones cover pelvis, chest, head, upper arms, forearms, hands, thighs, shins and feet. The head guide extends from the chin/neck pivot through the skull to its crown; selecting its crown marker selects the head bone. This guide does not enlarge the sprite or move its rotation pivot. Select a bone from the list or drag its joint. Local translations inherit the parent's rotation; angle edits move descendant joints, bound skin pixels, clothing and hand-held equipment. Bone transforms are bounded. A hidden-source toggle lets you replace a segment's original pixels with an authored part. Forward kinematics and integer pixel rasterization drive the sprite; this is not an inverse-kinematics or physics solver.

The initial clips are adapted from `PX.DOLL.POSES` into per-bone offsets. They are editable rig studies, not promises of pixel-identical game animation: the game still has its own specialized pose, weapon and outline rules in the appearance preview. Add named clips, duplicate/delete keyframes, set each frame to 50–2000 ms, mirror poses, choose looping or one-shot playback and optionally interpolate poses. Coordinates snap to pixels; interpolation is off by default. Previous-frame onion skin and a skeleton overlay aid editing and are excluded from exports. Turn off mirrored preview before dragging joints.

A project can hold 16 clips, 64 keyframes per clip and 32 authored parts. Undo/redo retains up to 60 project checkpoints. **New rig from appearance** makes a fresh rig from the selected character; Undo restores the previous project. Appearance changes update the rig's source character while retaining the animation and part library. Browser storage and project exports preserve the selected clip, frame, bone, part and view.

## Draw your own attached parts

Open **Create a bone-attached pixel part**, add a part and paint its transparent 16 × 16 grid. Light, Mid, Shade and Edge brushes store grayscale tone indices; Erase clears a pixel. The central cross is the bone pivot. Choose the attachment bone, material, local offset, visibility and whether it draws behind the body. Parts follow their bone's position and rotation automatically and use the character's runtime material palette. This supports custom hair, headwear, clothing pieces or accessories without PNG inputs. Use the original appearance slots or hide the corresponding source bone pixels to avoid overlapping replacements.

Export an individual grayscale source part PNG, a posed sprite PNG, or an entire clip PNG and its matching metadata. The full project JSON remains the editable source of truth. Drawings use binary alpha, with no smooth resampling of body pixels.

## Rig project and runtime API

**Save rig project** writes `ashmark-rig-project`, version 1: source appearance recipe, hidden source segments, authored grayscale parts, clips and per-keyframe bone transforms/durations. Optional `editor` metadata restores editor selection and view; runtime normalization ignores that UI metadata. This format is separate from ordinary appearance recipes and collections. The existing collection export also includes the rig project; older collections without one remain accepted.

```js
// The normal engine/game art scripts, sprite-engine.js and rig-engine.js are loaded.
const project = SpriteRig.read(savedRigJSON);
const clip = project.clips[0];
const sampled = SpriteRig.sample(clip, elapsedMilliseconds);
const frame = SpriteRig.render(project, sampled.pose);
context.drawImage(frame.image, x - frame.anchors.root[0], y - frame.anchors.root[1]);
const exportedClip = SpriteRig.sheet(project, 0);
// exportedClip.image: transparent native-pixel atlas.
// exportedClip.manifest: frame rectangles, durations, bone transforms,
// per-frame joint coordinates, anchors, equipment attachments and complete project data.
```

Rig canvases keep a common pelvis/root origin with space around the original body, growing to a larger power-of-two cell when required. The `root` anchor is the fixed bind-pose origin; `joints.pelvis` is the animated pelvis. Clip sheets align that origin at each cell's center, so a raised weapon or large part cannot recenter the character between frames. Each keyframe is exported once with its authored duration; interpolation remains an explicit runtime option. The preview's zoom, skeleton, ghost and editing grid are not in the exported pixels. Authored clip playback uses separate posed sprites and does not replace the live game's animation system automatically. Save projects and cache generated frames when integrating them into the game.

`rig-engine.js` contains binding, hierarchy, forward transforms, skinning, sampling and exports. `rig-editor.js` contains the interactive editor and persistence. `rig-tests.html` / `rig-checks.js` cover source-pixel parity for all races, actual bone deformation, hierarchy/gear binding, authored parts, clip timing, mirrored poses, project validation and PNG/metadata alignment.

## Create and inspect

Choose a starting preset, then edit a race from the current engine catalog (including Human, Dwarf, Elf, Orc and Goblin), hairstyle, facial hair, forward-facing eyes, skin/hair/team palettes, equipment slots, weapons and shields. The slots and part names come from `PX.DOLL` in `engine/doll.js`; this tool does not replace the approved drawings. A preset's cloth, armor, headwear and cloak remain editable parts. Gender-specific anatomy is not added: the existing sprite skeleton is shared.

Locks keep selected parts **and their materials** during seeded random generation and the 12-variation grid. Race and color-ramp overrides stay fixed. Variations are deduplicated by their recipe choices without counting the texture seed as a new design. They are not a facial-identity system; faces at this resolution have very few pixels. Named favorites and collections keep complete recipes. The session is stored locally when browser storage is available; export a JSON collection for a portable backup.

Material controls expose four explicit tones: light, mid, shade and edge. `team`, `hair` and `skin` are character channels; named materials are shared wherever used. A channel override takes precedence over the palette it refers to. Source pixels retain their channel number and tone index, so recoloring does not need PNG generation.

## Two preview renderers

- **Game figure:** the actual `sprites.js`, `people.js`, `figures.js`, `dollfigs.js` and `weapons.js` drawing code, loaded without the simulation. Standing, four walking frames, four running frames, and three frames each of swing, thrust and overhead attack. The selected weapon uses the game's own drawing and pose rules. These are art previews; timing/hit effects, targets, equipment stats and battle AI are not simulated.
- **Engine base + gear:** `PX.dollBase` / `PX.dollPaint` plus separate `PX.dollGear` attachments. The unchanged source cell is **17 × 19**. Supported animations are standing, four walking frames and the engine's single strike pose. Gear is laid on a larger transparent frame so pieces that extend outside the body cell are retained.

The engine's club has no corresponding game weapon renderer. Choosing its preset switches the workshop to Engine base; API rendering also identifies that fallback. The extended weapon list is available in Game figure view. Engine base draws only weapons that exist in `PX.DOLL.WEAPONS`; inspect their game view for other weapon types.

The native game view faces right; the other view is a mirror, with reflected attachment anchors. The raw engine base retains its native orientation, before the game's body remapping. This tool does **not** invent eight directional art or resample the drawings to 16 × 16.

The source inspector shows the assembled body without hand-held gear, separate gear and disjoint visible material masks. A mask does not reconstruct hidden garment pixels. PNG layer exports share the displayed base frame. Indexed JSON retains native **17 × 19** body indices, source anchors, the frame origin, and separate mirrored-display metadata. Gear is exported as independent positioned layers, not included in the body index.

## Export and integration

- **Recipe JSON:** `ashmark-sprite`, version 1, containing normalized choices, equipment, seed and four-tone ramp overrides.
- **Frame PNG:** current renderer, pose, frame, facing and grayscale setting; transparent, native pixels. Preview grid/anchor overlays are not exported.
- **Sheet PNG + metadata:** separate download buttons for phone/browser compatibility. Four columns, rows grouped by animation then facing. Game view exports 36 populated cells; Engine base exports 12. Unused cells stay transparent. Frame rectangles, relative anchors, FPS, grayscale flag and the exact recipe are saved in the matching JSON. Every cell shares the maximum required power-of-two frame size; drawings are bottom-aligned, centered and never resized.
- **Collection JSON:** current recipe, locks, 12 variations, named favorites and preview settings.

```js
// Within the workshop, or in a game that already loads its graphics scripts:
const recipe = SpriteStudio.read(savedJSON);
const frame = SpriteStudio.render(recipe, {
  renderer: 'game', pose: 'walk', frame: 2, left: false
});
context.drawImage(frame.image, x, y);
const sheet = SpriteStudio.sheet(recipe, {renderer: 'game', fps: 8});
// Save sheet.image as PNG and sheet.manifest as JSON.
```

`SpriteStudio.spec(recipe)` returns the corresponding low-level `PX.doll` specification with separate gear and no shadow. For colored low-level output, use `PX.dollPaint(PX.dollBase(spec), channel => SpriteStudio.ramp(recipe, channel))`. Cache finished frames in the game; create random recipes once and save them rather than rerolling while drawing.

Game previews temporarily supply the workshop's custom part specification to `dollSpec` during one synchronous draw, restoring it in `finally`. The game art scripts and their part tables are not modified. The independent tool's `runtime.js` only defines an absent world (`WM = null`); **do not load that file into the running game**. The production character creator is not wired to authored rig projects by this change.

## Editable sources

- `sprite-engine.js`: validated appearance recipes, palettes, renderer adapters, variations, masks and sheet metadata.
- `rig-engine.js`, `rig-editor.js`: editable bone rigs, animation clips, part painting and project persistence.
- `rig-tests.html`, `rig-checks.js`: focused skeletal authoring checks.
- `workshop.js`, `index.html`, `style.css`: controls, playback, inspection, browser storage and downloads.
- `runtime.js`: tool-only environment for shared game graphics scripts.
- `build.py`: bundles the repository's current source scripts into `sprite-workshop.html`.
- `tests.html`, `checks.js`: focused pixel parity, material masks, mirrors/anchors, race/preset/pose rendering, locks, deterministic generation, recipe validation and sheet alignment checks.
- `examples/index.html`: a generated four-race lineup using the same shared renderer.

Run `python "engine/sprite arts/build.py"` from the repository root after editing the source or pulling changes to shared graphics files. The standalone HTML intentionally contains a snapshot of the scripts at build time; `index.html` loads live sources. The editable ZIP includes the required shared scripts at their original relative paths. No production game files are changed by this workshop.
